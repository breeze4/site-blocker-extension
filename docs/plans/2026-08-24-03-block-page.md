# The block page

## Parent spec

`docs/specs/2026-08-24-01-reset-tokens.md` — see "Blocking and re-entry", the
"Blocking a tab" data flow, and the resolved decisions for the block target and
the manifest.

## What to build

Replace the silent bounce to the browser's new tab page with a real extension
page. When a domain is denied, the worker navigates the tab to a block page
carrying the domain and the URL that was blocked. The page names the site, states
that time is up, and gives the time until the site becomes usable again, measured
against the re-entry floor.

The content script stops replacing the page body as its primary path. Instead it
asks the worker to navigate, so both routes land on the same page. The body swap
survives only as a fallback for when that message fails.

No reset button yet — the token does not exist until the next slices.

## Goal

Every block, whether from expiry mid-visit or from navigating to an out-of-time
domain, lands on one extension-owned page that names the domain and says when it
becomes usable again.

## Implementation notes

Build the target with `chrome.runtime.getURL("blocked.html")` and append the
parameters with `URLSearchParams`, so encoding is handled for URLs that carry
their own query strings and fragments.

The page must not navigate the tab itself on load, and the content script must not
set `window.location` to an extension URL. A page-initiated navigation to an
extension resource requires `web_accessible_resources`, which would let any site
probe for the extension. Every navigation goes through the worker's
`chrome.tabs.update`, which is extension-initiated and needs no such entry.

The re-entry estimate is the wall-clock time for `timeLeft` to reach
`reEntryFloor(originalTime)` at the domain's recharge rate. The existing
`estimateSecondsUntilFull` computes the deficit to the cap, not to the floor, so
compute the floor deficit in the page rather than reusing that helper. If the
domain is already at or above the floor, the page states the site is usable again
instead of showing a countdown.

The content script's fallback body swap keeps the current copy. It is a
degraded path, not a second design.
